## Add navigation to an existing application

Assign stable IDs to authored notes or chords before composing. After layout, build a new snapshot. Supply source references if the host needs to map a selection back to its document.

```js
factory.draw({ retain: true });
const reading = new VexFlow.ScoreNavigation(composition, spec.staves, {
  'kit-1-3': 'kit/measure/1/event/3',
});
const option = reading.events.find(event => event.id === selectedID);
const hit = reading.hitTest(scoreX, scoreY);
```

Keep the selected ID when replacing the snapshot. Region coordinates are logical CSS pixels in the score. Convert a pointer from client to score coordinates before hit testing. The runnable example accounts for element offsets and axis-aligned CSS scaling. A hidden or compressed event can have a reading entry and no visible target. Grace groups, individual heads inside a chord and arbitrary custom tickables do not yet have separate reading entries. Native notation and rendering APIs continue to work without a reader. A rejected network font load now reports `FontLoadFailed` with the requested family. Await completion before laying out music that uses that face. ## Assistive technology review

Open **score-reader.html** from the CI artifact **web-notation-review**, or open the source example after running `npx grunt webpack:debug`. The artifact is self-contained and works offline. [Source example](../../demos/ui/score-reader.html)

1. Enable the screen reader and tab to **Score events**. Use the normal list interaction for that browser and reader. Check whether the list has a useful name and the current event is announced once.
2. Read the first six events. Expect flute C5, bass drum, flute B4, a drum rest, flute G4, and a snare/hi-hat chord. The first four are quarters and the last two are halves. Verify that measure, staff and duration are intelligible.
3. Keep the kit chord selected. Change **Renderer** to **Canvas** and **Layout** to **Narrow**. Return to **Score events**. Check that the selected chord survives and the next event starts measure two.
4. Check visible focus and the highlighted note. On a touch device, select a visible note and rotate or resize the viewport. Record device, OS, browser, reader, outcome and any confusing announcement.

## Text and export findings

Use a matching face for both SVG text and outline comparisons. Firefox's SVG text bounds include advance space which can exceed painted ink. The test compares canvas ink with the outlined path, allowing 3 CSS pixels at the sample size. All three engines exported the accented Latin word and preserved the original decomposed text in live SVG. WebKit measured the decomposed form of “Café” about 1.2 CSS pixels wider than NFC on the local reference machine. Callers that need that width to repeat can supply NFC. Arabic/Hebrew phrase layout reports unsupported shaping. Live SVG retains Han text; attempting to outline it with only this Latin face identifies the missing character. ## Performance

M7 measures the complete interactive update, including the reading index, on an Apple M3 using pinned Chromium. The duet has six events per measure. Retained and fresh geometry, event order and height must match after every resize. The small-score budget is 100 ms at p95. Review a reproducible median regression above 10% on identical hardware. Shared CI runners report timings for diagnosis.

| Measures / events | Repeats | Retained median / p95 (ms) | Fresh median / p95 (ms) |
| --- | ---: | ---: | ---: |
| 4 / 24 | 20 | 4.0 / 5.7 | 4.7 / 6.3 |
| 16 / 96 | 8 | 9.3 / 9.6 | 11.7 / 14.6 |
| 48 / 288 | 5 | 25.1 / 27.6 | 30.5 / 33.6 |

The benchmark separately times construction, layout, drawing and live SVG serialization for the M0 piano workload. A fixed-width edit experiment replaces one or two independent bars and checks every SVG path, text and rectangle against a clean rebuild. This experiment assumes no spans or spacing dependencies cross the edited bars. The JSON report includes all phase medians, the local-edit measurements and Chromium heap/DOM samples after forced GC at 8, 16, 24 and 32 create/reset cycles. These samples describe the tested session; long-running production sessions still need profiling. [Performance tests](../../tests/web/performance.mjs)

## Reproduce and maintain the gate

From the repository root, install the usual dependencies, then run:

```sh
npm ci --prefix tests/web --ignore-scripts
(cd tests/web && npx playwright install chromium firefox webkit)
npx grunt webpack:debug
VF_WEB_REFERENCE=/path/to/approved-main/build/cjs/vexflow-debug.js node tests/web/qualify.mjs
```

Build the reference independently at the revision pinned by `VF_ENGRAVING_REFERENCE` in the [CI workflow](../../.github/workflows/web-qualification.yaml) using its lockfile and `npx grunt clean:webpack_cache webpack:debug`. On Linux, pass `--with-deps` to the browser install. Supply `chromium`, `firefox` or `webkit` after the script to isolate one engine. The reports, PNGs, accessibility snapshots and standalone reader are written under `build/m7/`. The full gallery command, pinned historical release checksum and independent-main setup are in the baseline guide. Add `--playwright` to that command to use the same Chromium build as the web matrix. [Baseline instructions](m0.md)

For an intended visual change, inspect the before/after at full size, record the reviewer, case and reason in the engraving manifest, and advance the reviewed revision in the runner and workflow after acceptance. The release comparison remains pinned to 5.2.0. CI publishes the reports and images even on a failing comparison. [Fixture manifest](../../tests/engraving/manifest.json)
