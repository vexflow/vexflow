## Using the VF5 additions

Create one profile per score and pass it to the Factory. Font registration follows the existing browser or Node procedure. A profile accepts the optional JSON shipped by the selected font. The library makes no network requests for metadata.

```js
const engraving = new EngravingProfile({ musicFont: 'Petaluma', metadata, clearance: 0.25 });
const factory = new Factory({ renderer, engraving });
const score = factory.EasyScore();
const notes = score.notes('G4/8, A4/8', { stem: 'up' });
const beam = factory.Beam({ notes });
const system = factory.System({ width: 320 });
system.addStave({ voices: [score.voice(notes, { mode: 'soft' })] });
system.format();

const noteGeometry = measureEngraving(notes[0], { paddingPx: 2 });
const beamGeometry = measureEngraving(beam);
```

- Measure after assigning staves and formatting. Coordinates use renderer pixels with x increasing rightward and y downward. A head anchor uses its ink center in x and its pitch line in y. A stem has separate base and tip anchors. A curve has shifted start and end anchors. A lyric exposes its text baseline.
- `parts` encloses the marks contributed by the element and supported children. `ink` is their union. `layout` adds the requested padding on all sides. For a beamed passage, measure the notes and the beam. Stems belong to notes and filled strips belong to beams. Curves include a conservative stroke envelope. Tie ribbons use the hull of their quadratic control points. Shadows and selection overlays are outside the ink contract.
- Check `diagnostics` before using bounds. An unsupported child gets its own source ID, and supported siblings still contribute. A custom subclass can supply a geometry callback, including an explicitly empty shape. The optional viewport reports overflow. An empty result has no union box. [Geometry API](../../src/engravinggeometry.ts)
- An explicit note family wins over the Factory profile. A font mismatch uses native stem anchors. Supported SMuFL stem coordinates use four staff spaces per em and y points upward in the font. An explicit beam thickness in staff spaces wins over font metadata, which falls back to 0.5 spaces. Beam clearance defaults to 0.25 spaces. A native beam-width override in pixels wins at draw time. Profiles copy the supported metadata and freeze it. [Profile implementation](../../src/engravingprofile.ts)
- Profile coverage includes Factory pitched and grace notes, their heads and flags, articulations, accidentals, clefs and composed key and time signatures. Text families, tab-specific glyphs and directly constructed native elements retain their existing font selection. Register fonts before measuring.

## Pre-draw geometry audit

The existing public-module inventory supplies the checklist. The distinction matters for contributors adding a collision consumer. A formatter width can reserve space without enclosing every mark the element will draw. [Module inventory](../easyscore-coverage.json)

| Participants | Measurement and drawing boundary | Coverage and next use |
| --- | --- | --- |
| StaveNote, NoteHead, Stem, Flag, ledger lines | The parent positions each head, flag and stem in page coordinates. Displaced heads, flag shortening, ledger width and stroke thickness contribute separately. | Use the formatted parent for these owned parts. The native Stem also exposes its segment and bounding box once positioned. |
| Beam | The same sloped strips drive drawing and bounds, including partial and secondary beams. Reformat releases the previous fit before solving for the new width. | A beam tests another voice’s head at every attack in its time range. M1 covers single-stave, same-direction sloped groups. M2 takes up slope choice and broader obstacle policies. |
| Articulation, Annotation | Layout resolves the snapped articulation position and annotation baseline before either glyph draws. | The stacked-mark fixture, lyric-row prototype and pixel check exercise these positions. |
| GraceNote, GraceNoteGroup, Curve, plain StaveTie | Position grace children first. Then measure their stems, slashes, beams and optional tie. Curves use Bézier extrema. | The adapter recursively includes these children. Labeled ties, tab ties and slides need separate text or shape adapters. |
| ChordSymbol, TextDynamics, inline clef, key and time signatures | VF5 already has class-specific metrics or boxes. Some depend on the last render position or describe a reservation. | Preserve the native APIs. Add full, positioned ink contracts as chord, boundary and dynamic consumers need them. |
| Accidentals, dots, ornaments, tremolos, fingering, string numbers, strokes, parentheses, vibrato, bends | ModifierContext reserves space. Individual draw methods place signs, auxiliary glyphs, paths or labels. | These drawables need independent pre-draw adapters. Their IDs surface in diagnostics when attached to a measured note. |
| Tuplets, hairpins, pedal, stave lines, text and vibrato brackets | Endpoints or occupied lanes depend on notes, text or the row. | The persistence prototype draws a linked pedal fragment per intersected row. General span measurement and routing remain M2–M4 work. |
| Tab and grace tab notes, GlyphNote, RepeatNote, GhostNote, TextNote, ClefNote, KeySigNote, TimeSigNote, BarNote, NoteSubGroup, Crescendo, multi-measure rests | These include silent timing events, glyphs, text and compound groups with different ownership. | Each future adapter must declare empty ink or include its visible children. A generic Element text box cannot supply this distinction. |
| Staves, connectors, barlines, clefs, repeats, section marks, tempos, stave text, voltas | Stave and System boxes describe staff or layout extents. Boundary glyphs and above-staff text can extend beyond them. | M4/M5 need positioned boundary material and staff envelopes. |
| Voice, TickContext, ModifierContext, Formatter, System, Sheet | These supply timing, alignment, placement and row ownership. Their reservations are layout inputs. | Use the rhythmic anchors and participating drawables for collision work. Renderers, caches, parsers and music-theory utilities own no engraving ink. |

## What the prototypes established

| Fixture or consumer | Acceptance evidence |
| --- | --- |
| Beam between attacks | A second voice enters between two beamed eighths. Moving that head into the original beam envelope shortens the group’s stems enough to clear it. A distant pitch is the control. The reviewed shared-attack case still passes. |
| Retained layout | A sloped beam, displaced chord, flag, grace group with slash and slur, stacked articulations and a curve are measured before drawing. Repeated measurement and drawing agree. Returning from 255 to 450 pixels reproduces a fresh 450-pixel layout. |
| Lyrics and cross-staff notes | A lyric row uses measured obstacles and a shared baseline. A second pass excludes the previous lyric placement. A voice displayed on two staves supplies absolute stem anchors to the same beam. |
| Score-local settings | Two live Factories alternate Bravura and Petaluma. The tests check actual glyph families, distinct head widths, beam thickness, metadata anchors and the first score’s geometry after drawing the second. Missing and malformed metadata produce finite fallback geometry. |
| Logical score and excerpt | Two independent wire layouts reopen in a fresh Node process. The VF5 adapter renders at 720 and 250 pixels. The rehearsal mark appears once, the dynamic follows its event, and the lower-staff pedal releases at the half-bar attack. Restoring the width restores the pixels. A preceding bar insertion preserves references. |
| Diagnostics | Tests exercise unsupported native input, a dangling pedal endpoint, an unsupported geometry child, invalid extension coordinates, measurement before formatting and viewport overflow. |
