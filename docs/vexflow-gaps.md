# VexFlow notation gap register

Created: **2026-11-16**

Last reviewed: **2026-11-16**

Baseline: **`a7585866c176401d76c2a3ca66217454abb5c685`**, package version `5.1.2`

## Assessment

VexFlow already has a broad notation vocabulary and useful low-level control. The largest remaining gap is consistent engraving when those elements interact, followed by the ability to lay out a complete score without extensive application-specific positioning.

The recommended order is:

1. Establish an engraving corpus and reliable geometry before changing algorithms.
2. Improve spacing, polyphony, accidentals, beams, ties, slurs, and collision avoidance.
3. Add score-aware system breaks, spanning marks, lyrics, and pagination.
4. Complete mainstream instrument workflows and web delivery contracts.
5. Expand specialist notation through explicit, tested profiles.

Do not equate glyph availability with notation support. A symbol needs construction, musical anchoring, spacing, collision behavior, continuation, styling, and tests. Likewise, an attractive single example does not establish that an algorithm handles the feature generally.

### Scope and evidence limits

This is a source/documentation audit and online comparison, not a new visual certification. It examined public modules, relevant implementation paths, test families, current documentation, the CI workflow, and issue search results. Existing tests and historic reproductions were not executed for this planning task. No claim below means all repertoire or all combinations have been tested.

The baseline is this checkout, **not a claim about the published npm package or the default branch**. In particular, the checkout contains early EasyScore work. Source links below are relative to this repository; use the recorded commit when comparing future changes.

GitHub research was read-only: open issues in `vexflow/vexflow` and `0xfe/vexflow`, plus a sample of 80 recently updated closed issues in the current repository. Old reports are candidate regressions, not automatically current bugs. This is not issue triage or issue migration.

The maintainer confirmed on 2026-11-16 that [#354: EasyScore coverage](https://github.com/vexflow/vexflow/issues/354) and [#356: interactive guide](https://github.com/vexflow/vexflow/issues/356) are **in progress in parallel**. Preserve their ownership and plans. [#355: legacy issue reconciliation](https://github.com/vexflow/vexflow/issues/355) is an existing related tracker; its execution status was not established here.

## Quality target

A first-class web notation system should satisfy three independently testable levels:

| Level                 | What users should be able to rely on                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Engraving core        | Correct musical timing and attachment; readable automatic spacing; stable layout and drawing; deliberate manual overrides.                           |
| Optional score layout | Multiple measures, staves, systems, and pages; correct continuations and boundary symbols; publication-quality defaults for supported repertoire.    |
| Web integration       | SVG/Canvas parity, predictable font loading, responsive reflow, accessible semantic hooks, usable diagnostics, and measured large-score performance. |

Initial repertoire: educational examples, lead sheets, vocal/choral music, keyboard music, small ensembles, modern percussion, and fretted strings. Full orchestral publishing comes in stages. Historical notation and contemporary experimental notation need separate profiles. No finite register can claim to exhaust every notation tradition.

Playback, a graphical editor, collaborative editing, audio synthesis, and optical music recognition are not prerequisites for the engraving core. Importers, instrument catalogs, part extraction, and advanced score transformations can be optional packages or downstream integrations.

## Register conventions

Stable IDs are permanent. Split a large item into suffixed children, such as `VF-015a`, without renumbering existing entries.

**Priority** is product impact and dependency, not implementation order alone:

- **P0 — foundation:** blocks trustworthy implementation or acceptance of many other gaps.
- **P1 — core quality:** required for reliable mainstream engraving or complete-score delivery.
- **P2 — breadth:** important workflows that can follow the core release or ship as modules.
- **P3 — specialist:** needs a named repertoire, reviewer, and explicit scope before scheduling.

**Evidence:** `D` = documented limit or direct implementation constraint; `A` = audit inference from the inspected surface; `R` = external report requiring reproduction. `A` never proves impossibility through custom drawing.

**Status:** `Open`, `Investigate`, `In progress`, `Blocked`, `Verified`, `Deferred`. `Verified` requires the closure evidence described below. All entries were last reviewed on the date at the top unless an exception appears in the update log. Owners and issue/PR links are initially unassigned except for the parallel work explicitly identified. Milestones refer to the companion plan; they are proposed delivery targets, not commitments.

### Books and editorial review

- **Elaine Gould, Behind Bars.** Use as the principal modern engraving reference. Faber's [General Conventions description](https://www.fabermusic.com/news/new-behind-bars-general-conventions-published-22062023) identifies topics including chords/ties, accidentals, grace notes, metre and tuplets. Use the complete edition for broader instrumental and score questions.
- **Kurt Stone, Music Notation in the Twentieth Century.** [Publisher listing](https://wwnorton.com/books/9780393950533). Use in specialist contemporary-notation review, alongside current performer practice.
- **Gardner Read, Music Notation: A Manual of Modern Practice.** [Bibliographic record](https://ci.nii.ac.jp/ncid/BA27470789). Use as a comparative reference where conventions differ.

The books were identified through online publisher/catalog information; their complete texts were **not** reviewed for this audit. Do not invent page citations or claim book conformance. During implementation, a reviewer should record edition, section/page, a paraphrased rule, and an original test example. Editorial alternatives should become named policies, not competing hard-coded fixes.
